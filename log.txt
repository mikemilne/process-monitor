Sysmon install is a persistent system-wide change (kernel driver SysmonDrv + service
  Sysmon64), independent of this test session - it keeps running after this script
  exits. To remove it entirely: Sysmon64.exe -u (from C:\Users\mmilne\Documents\sysmon-setup).

PID cross-referencing caveat: InInitialCapture/InSessionBaseline match on raw PID
  against first_pidlist.csv / session_baseline_pidlist.csv. Windows recycles PIDs,
  so a "Yes" only means some process held that PID at capture time - it is not proof
  it's the same process instance as the one in the Sysmon event. ProcessGuid (stable,
  never reused) is the reliable identifier for correlating a process's own Create/
  Terminate/NetworkConnect/DnsQuery events with each other.

DnsQuery.QueryStatus is a Win32 error code, not a DNS RCODE: 0 = success,
  9003 = DNS_ERROR_RCODE_NAME_ERROR (NXDOMAIN) - seen on the agent-nxdomain events
  against mcp-agent-test.invalid (RFC 2606 reserved TLD, guaranteed to never resolve
  - used deliberately as a safe negative-case DNS query).

Test agent targets (real public APIs, no API key required):
  agent-openmeteo -> api.open-meteo.com  (Open-Meteo weather API)
  agent-noaa      -> api.weather.gov     (NOAA/NWS API; requires only a descriptive
                                           User-Agent header, which mcp-test-agent sets)
  agent-nxdomain  -> mcp-agent-test.invalid  (deliberately unresolvable, negative case)
These stand in for "an agent with a remote MCP connection": the actual weather-mcp.dev
  npm package (@dgahagan/weather-mcp) runs locally over stdio and would need Node.js
  (not installed on this machine) plus a NOAA_API_TOKEN; it calls these same two
  backends under the hood, so hitting them directly produces equivalent Sysmon
  telemetry without adding a Node.js dependency or executing an unvetted third-party
  package.
